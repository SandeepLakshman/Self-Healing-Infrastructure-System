ShopSphere — Self-Healing E-Commerce Platform & Cloud-Native Infrastructure

Docker Multi-Stage Kubernetes Minikube (3 Replicas) Node.js 20 LTS Express React 18 + Vite 5 Tailwind CSS 3

ShopSphere is a high-availability, production-style e-commerce web application engineered with a modern monochrome glassmorphism frontend, an Express REST API backend, Docker multi-stage containerization, a 3-replica Kubernetes self-healing infrastructure with automated health probes, and an automated GitHub Actions CI/CD pipeline.

🎯 Project Overview & Objectives

In production environments, infrastructure failures (crashed pods, memory spikes, unexpected process exits) must be isolated and resolved automatically without downtime or degraded end-user experience.

  1. Realistic Commercial Experience: Monochrome luxury storefront with frosted glassmorphism, multi-category catalog (33 items), instant search, price slider filter, persistent cart state, and simulated checkout.
  2. Autonomous Self-Healing: 3 backend replicas behind a Kubernetes ClusterIP load balancer with automated livenessProbe and readinessProbe monitoring on /api/health.
  3. Container-Native Architecture: Decoupled frontend (Nginx reverse-proxy) and backend Docker containers with explicit resource requests and limits.
  4. CI/CD Quality Gate: Automated GitHub Actions pipeline validating frontend builds, backend health checks, and container image generation on every push.

🚀 CI/CD Pipeline (GitHub Actions)

An automated continuous integration workflow is configured at .github/workflows/ci.yml. It validates every commit and pull request on Ubuntu runners without requiring paid cloud infrastructure or secrets.

Pipeline Stages

  1. Frontend Job: Installs dependencies with npm caching, compiles production assets via Vite (npm run build).
  2. Backend Job: Installs dependencies, runs syntax integrity and API route health checks (npm test).
  3. Docker Build Job: Builds production shopsphere-backend:1.0.0 and shopsphere-frontend:1.0.0 container images upon successful CI checks.

☸️ Kubernetes Deployment (Minikube)

# 1. Start Minikube & load images
minikube start --driver=docker
minikube image load shopsphere-backend:1.0.0
minikube image load shopsphere-frontend:1.0.0

# 2. Deploy manifests
kubectl apply -f k8s/

# 3. Verify pods & services
kubectl get pods -o wide
kubectl get svc

🔄 Self-Healing Demonstration

Test the cluster resilience by terminating a pod:

# Step 1: Watch pods in terminal 1
kubectl get pods -l app=shopsphere-backend -w

# Step 2: In terminal 2, delete one backend pod
kubectl delete pod <backend-pod-name>

# Step 3: Observe zero downtime on http://localhost:8080/api/health
# ReplicaSet controller instantly launches a new healthy replacement replica!
